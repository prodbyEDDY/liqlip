## §0. Резюме

Liqlip — отдельное Windows-приложение «только буфер обмена», вынесенное из Liquid Tools
(Tauri 2 + Svelte 5). Шелф выглядит как в Liquid Tools, но переделан под клавиатуру и надёжную
вставку; плюс просмотр, меню действий, мультивыбор, преобразования, папки, сниппеты, очередь
вставки, OCR, приватность по умолчанию, классическое окно настроек. Репозиторий
`prodbyEDDY/liqlip` (приватный), папка `LiquidTools/liqlip/`. Liquid Tools не меняется.

**Сейчас:** W0–W2 приняты и слиты (2026-11-26), установщик 1.0.0 собирается. Идёт W3 — ревью свежими
глазами и исправления по четырём зонам. Eddy поручил довести приложение до готового полностью
автономно (§11).

## §1. Модель работы

- Координатор пишет промпты и ревьюит; код пишут агенты **Opus 5.5, reasoning xhigh** (решение Eddy).
- Волны: W0 последовательно (фундамент) → W1 параллельно в git-worktree по одному на агента
  (непересекающиеся модули; контракт и заглушки команд уже стоят после W0) → интеграция
  координатором → W2 параллельно → W3 ревью/полировка → установщик → живая проверка Eddy → W4 фиксы.
- Worktree волны: `C:\Coding\My Projects\LiquidTools\liqlip-wt\<задача>` на ветке
  `w<N>/<задача>`; координатор сливает в `main` по порядку приёмки из dispatch-документа.
- Агенты нативное приложение не запускают (правило воркспейса); проверка — гейты из
  ARCHITECTURE §12, браузерный прогон UI на мок-адаптере, Rust-тесты (`cargo test` работает с W0).
  Живой прогон — за Eddy после каждой волны с установщиком.

## §11. Журнал решений

### 2026-11-25 — Liqlip: отдельный менеджер буфера обмена

**Контекст:** Eddy попросил вынести буфер обмена Liquid Tools в отдельное Windows-приложение
«Liqlip», выглядящее так же, но проработанное до максимальной глубины (Raycast как ориентир),
с простым привычным окном настроек; Liquid Tools не трогать; работа волнами агентов Opus xhigh
под оркестрацией `/lead`. Проведена разведка: фронтенд и Rust-бэкенд буфера Liquid Tools
(отчёты агентов в этой сессии) и конкурентный анализ (Raycast для Windows v2.13, Paste, Maccy,
Ditto, CopyQ, Win+V, PowerToys Advanced Paste) + платформенные факты Windows.
**Решение (ответы Eddy в `AskUserQuestion`):**
- Новый приватный репозиторий `prodbyEDDY/liqlip` + перенос кода (без истории Liquid Tools).
- Хоткей по умолчанию `Alt + V` (как в Liquid Tools; конфликт при одновременном запуске
  обрабатывается понятной ошибкой и предложением сменить).
- Импорт истории из Liquid Tools — по кнопке (онбординг и настройки), без снимков и диктовок.
- Своя документация и ROADMAP в репо Liqlip; правило воркспейса «один ROADMAP» → «один ROADMAP
  на продукт».
- Модули v1 сверх ядра: **сниппеты**, **OCR по картинкам**, **очередь вставки**; шифрование БД — v2.
- Шелф: как в Liquid Tools + просмотр по Space + строка подсказок с целевым приложением.
- Действия карточки: по наведению/выбору, 3 кнопки (копировать, избранное, ⋯).
- Настройки: классическое окно Windows с сайдбаром.
**Решения координатора (могут быть пересмотрены Eddy):** лента «Все» хронологическая
(избранное — своей пилюлей, опция «избранное первым»), чтобы `Ctrl+1` = последнее копирование;
глобальная дедупликация с подъёмом наверх; шелф по хоткею активируется (клавиатура сразу),
фокус возвращается цели перед вставкой; listener вместо опроса; учёт четырёх приватных
маркеров Windows (иначе Bitwarden утекает); `SendInput` вместо `enigo`; своя схема SQLite
(FTS5 trigram, мягкое удаление, форматы для «Вставить как…»); dev-порт 1430.
**Причина:** главные слабости буфера Liquid Tools — мёртвая клавиатура в режиме по
умолчанию, 1D-навигация, отсутствие просмотра/меню/мультивыбора/undo, пароли в открытом
виде, опрос с потерей изменений, дедупликация по 280 символам, вставка без отпускания
модификаторов и без учёта UIPI.
**Последствия:** `docs/SPEC.md`, `docs/ARCHITECTURE.md`, этот файл, промпты W0/W1; в корневом
`CLAUDE.md` воркспейса добавлен Liqlip.

### 2026-11-26 — Полная автономия до готового приложения

**Контекст:** при приёмке W0 Eddy ответил на открытые вопросы (запуск W1; PQ-02) и поручил
координатору довести Liqlip до готового приложения без промежуточных согласований, включая OCR,
импорт и всё, что входит в SPEC; крупных синтетических стендов (50 000 записей) не делать.
**Решение:**
- Волны W1 → INT-1 → W2 (OCR, импорт и бэкап, оверлеи шелфа, упаковка) → W3 ревью → W4 фиксы →
  итоговый установщик идут подряд, без остановок на вопросы. Продуктовые развилки решает координатор
  по SPEC и фиксирует здесь.
- Коммиты и пуш в `main` репо Liqlip — координатор, после приёмки каждой волны.
- PQ-02: агенты волн нативно не запускают (шесть экземпляров конфликтуют за `Alt+V`, буфер и
  single-instance, а агент вставки печатал бы в чужие окна); координатор запускает приложение на
  интеграции для сквозных сценариев.
- Без стендов на 50 000 записей: скорость — по построению (индексы, keyset-курсор, FTS,
  виртуализация) с проверкой планов запросов; тесты — малые и с уборкой временных файлов. W1 и W3
  собирают Rust в один общий каталог `liqlip/src-tauri/target`, а не по 6 ГБ на worktree.
- PQ-01 и PQ-03 закрыты решениями координатора (§10.3).
**Причина:** решение Eddy.
**Последствия:** правки в `.claude/commands/lead.md`, `CLAUDE.md`/`AGENTS.md`, ARCHITECTURE §12,
SPEC §7, промпт W1-A и dispatch W1.

**Решение:**
- Отдельный агент W2-E (Opus xhigh) — аудит и переработка всего UI: шелф, HUD, настройки, общие
  компоненты, токены. Правила:
  - никаких обводок, кроме `:focus-visible`;
  - никаких обрезаний;
  - концентричные радиусы из токенов (внутренний = внешний − отступ);
  - единый сквиркл;
  - выразительные превью по видам;
  - контраст AA;
  - новая `docs/design-system.md`.
- Требование «шелф 1:1 с Liquid Tools» снимается там, где мешает качеству; идентичность (монохром,
  liquid, сквирклы) остаётся.
- W2 идёт в две ступени: A/B/D/E параллельно, слои шелфа W2-C — после E, на его примитивах.
- UI разделов OCR, импорта и «О Liqlip» (сделан W1-F на моке) полирует E. Бэкенд-агенты A/B/D UI
  не трогают.

**Причина:** итоги ревью дизайна; строить слои на неотполированной системе — двойная работа.

**Последствия:** промпты W2-A/B/D сужены до бэкенда. Добавлены промпт W2-E и dispatch W2. Живой
прогон перенесён на установленную сборку (INT-2).

### 2026-11-26 — W2 принята, живая проверка — на установленной сборке

**Контекст:** после слияния W2 собран установщик 1.0.0 и тихо установлен для текущего пользователя.
