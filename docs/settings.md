# Окно настроек и онбординг (реверс-док)

> Что сделано в окне `settings` и как оно устроено. Продуктовые требования — [SPEC.md](SPEC.md) §4
> (разделы и поля), §2.4, §3.9–3.12; контракт — [ARCHITECTURE.md](ARCHITECTURE.md) §9 (+ §9.9).
> Владелец — W1-F; вид переработан в W2-E ([design-system.md](design-system.md)). Замер:
> 2026-11-26 (W2-E: все разделы и онбординг на моке, 720×520 и 1200×800, обе темы, RU/EN;
> нативно не запускалось).

## 1. Окно

Классическое окно Windows: системный заголовок рисует Windows (свой не делаем), слева разделы,
справа группы настроек, изменения применяются сразу. W0 создаёт окно 960×680, минимум 720×520,
`CloseRequested → hide`. Точка входа — `settings.html` → `src/windows/settings/settings.ts`
(`initAppearance()` до монтирования) → `SettingsWindow.svelte`.

**Почему `SettingsWindow.svelte`, а не `Settings.svelte`** (как в ARCHITECTURE §10): стор по
договорённости называется `settings.svelte.ts`, и на регистронезависимой ФС Windows импорт
`./settings.svelte` разрешался в компонент `Settings.svelte`. Корень переименован.

| Файл | Что |
|---|---|
| `SettingsWindow.svelte` | корень: сайдбар + контент или онбординг; навигация; оптимистичная тема/язык; хосты тостов и диалогов |
| `settings.svelte.ts` | стор настроек (поверх `sync.ts`) |
| `sync.ts` | чистая очередь оптимистичных правок (тест `settingsSync`) |
| `logic.ts` | чистая логика: пути, ошибки полей → ключи i18n, размеры/числа, валидация имён, exe, проверки хоткеев, пауза, навигация (тест `settingsLogic`) |
| `sections.ts` | реестр разделов (ключ = `settings:navigate.section` = `?section=`) |
| `sections/*.svelte` | General, Picker (+ `Folders`), Hotkeys, Storage, Privacy, Snippets, Ocr, Import, About |
| `snippets/*.svelte` | редактор сниппета: `BodyEditor` (подсветка), `Reference` (справочник), `SnippetEditor` |
| `onboarding/Onboarding.svelte` | онбординг первого запуска |
| `ui/*.svelte` | локальные компоненты окна: `Group`, `Row`, `SidebarNav`, `HotkeyRow`, `PositionPicker`, `ExeList`, `RunningAppsDialog`, `AppIcon`, `TextInput`, `SkeletonRows`, `ImportProgressBar`, `DialogHost`, `ToastHost` |
| `ui.svelte.ts` | сервисы окна: один тост (с действием «Отменить») и один модальный диалог (промисы) |

## 2. Стор настроек

`settings.svelte.ts`: `settings_get` при старте (`status: loading → ready | error`, скелетон /
экран ошибки с «Повторить»), `settings:changed` → новое подтверждённое состояние, при показе окна
(`visibilitychange`) — тихий `settings_get` (окно только прячется, а `window.settingsBounds` Rust
пишет без рассылки). Дефолтов в UI нет — всё из `settings_get`; исключение — значения кнопки
«Сбросить» у хоткеев (`logic.ts::HOTKEY_DEFAULTS`), их равенство Rust-дефолтам держит тест
против `tests/fixtures/settings.default.json`.

`sync.ts` (движок):

- `confirmed` — последнее состояние от бэкенда; правка = патч `path = value`, сразу виден в UI.
- Запросы `settings_set` идут по одному; правки, сделанные пока запрос в полёте, уходят одним
  следующим запросом поверх нового `confirmed` (ничего не теряется, порядок сохраняется).
- Отказ команды → откат только патчей этого запроса, поле получает `failed` («Не сохранено.
  <причина по коду>»).
- Ответ `settings_set` проверяет **весь** объект (движок хоткеев спрашивается каждый раз), поэтому
  его `errors` **заменяют** прежние `taken`/`invalid`: конфликт, который исчез, пропадает, который
  остался — приходит снова. `failed` других правок живут до правки своего поля.
- `recheck()` — повторно отправить текущее состояние (проверка конфликтов);
  `settings.watchConflicts()` делает это при открытии раздела «Горячие клавиши» и шага онбординга
  и затем раз в 30 с, пока у какого-то хоткея `taken` (движок сам повторяет регистрацию раз в 30 с).

Сообщения у поля — `fieldErrorKey(field, code)`: `hotkeys.*: taken` → «Сочетание занято другим
приложением (возможно, Liquid Tools). Выберите другое.», `invalid` → «Это сочетание нельзя
использовать…», `picker.pasteKeys`/`privacy.ignoredApps`, `picker.monitor`, `ocr.language`, прочее →
«Это значение нельзя сохранить». Тема и язык окна применяются оптимистично (эффект в корне) и
откатываются вместе с правкой.

## 3. Навигация

Сайдбар (`SidebarNav`): одна точка Tab, ↑/↓/Home/End двигают фокус, Enter/Space открывают раздел;
выбранный — токен `selected`. `Ctrl+Tab` / `Ctrl+Shift+Tab` (и `Ctrl+PgDn/PgUp`) — следующий /
предыдущий раздел (не во время онбординга и открытого диалога). `settings:navigate { section }` —
переход (`"onboarding"` — показать онбординг), `?section=` — для браузера, синхронизируется
`replaceState`. Узкое окно (< 860 px) — сайдбар из иконок (подпись — `aria-label` + `title`), сниппеты
и сетки складываются в колонку. Контент прокручивается отдельно от сайдбара, ширина ≤ 780 px.

## 5. Онбординг

Показывается вместо сайдбара, если `settings.general.onboardingDone === false` (режим берётся из
настроек, а не из события: первый `settings:navigate` приходит раньше подписки), а также по
`settings:navigate { section: "onboarding" }` и `?onboarding=1`. Слева — список шагов (выполненные
с ✓, текущий — `selected`), сверху — полоса прогресса, «Шаг N из M».

1. **Привет** — что такое Liqlip, три возможности.
2. **Сочетание** — текущее `hotkeys.summon` (запись тем же `HotkeyRow`), при входе — `recheck()`
   («Проверяем…» → «Готово — другие приложения его не используют» или `taken` у поля), при `taken` —
   свободные варианты (`Ctrl + Alt + V`, `Alt + Shift + C`, …) одним щелчком.
3. **Приватность** — что не сохраняется + редактируемый список игнорируемых приложений.
4. **Импорт** — только если `import_lt_probe.found`; импорт с прогрессом и отчётом.
5. **Готово** — «Скопируйте что-нибудь и нажмите `Alt + V`» (реальное сочетание).

«Далее» / «Назад» / «Пропустить настройку» (= завершить). Завершение: `onboardingDone = true` →
обычные настройки + тост «Liqlip готов — нажмите …»; если сохранить не удалось — тост с причиной
(онбординг покажется при следующем запуске).

## 6. Развёртка плейсхолдеров (`src/lib/snippets/expand.ts`)

```ts
expandSnippet(body, { now, clipboard, uuid, locale? }) → { text, caretBack, caretIndex }
parseSnippet(body) → SnippetToken[]        // подсветка и диагностика
formatDate(date, format, locale) · applyOffset(date, "+2d") · parseOffset · caretSteps(s)
```

- `{clipboard}` · `{date}` `{time}` `{datetime}` `{weekday}` с `format="…"` и `offset="…"` · `{uuid}` ·
  `{cursor}` · модификаторы `| uppercase | lowercase | trim` (слева направо) · `{{` / `}}` — скобки.
- Формат: `yyyy yy MMMM MMM MM M dddd ddd dd d HH H hh h mm m ss s tt`, `'текст'` — как есть;
  `MMMM` рядом с днём — родительный падеж в русском («26 ноября»). Без `format` — формат локали.
- Сдвиг: `[+-]N` + `m h d w M y`, цепочки `+1d-2h`, части без знака наследуют предыдущий; конец
  месяца прижимается (31 янв + 1M = 28/29 фев).
- Плейсхолдер — `{` сразу с буквой и `}` в той же строке; иначе это текст (код, JSON не трогаем).
  Ошибочный плейсхолдер (неизвестное имя, атрибут, модификатор, формат, сдвиг) вставляется как
  написан и помечается; второй `{cursor}` выбрасывается.
- `caretBack` — нажатия ← после вставки (контракт W1-C, `text_paste.caretBack`): по одному на
  кодовую точку (суррогатная пара — одно), CRLF — одно нажатие.
- Локаль — решает вызывающий (настройки передают язык интерфейса), `uuid` — генератор вызывающего.

## 7. Состояния, дизайн, a11y

Вид — по [design-system.md](design-system.md) (W2-E).

- **Окно:** фон `ground`; сайдбар 220 px (< 860 px — иконки 64 px) без своей подложки, пункты —
  капсулы 36, выбранный — `raised` + `shadow-card`, подпись и иконка `ink` (без обводки).
  Контент прокручивается отдельно, стоит рядом с сайдбаром и ограничен 760 px — на 1200 px не
  растягивается и не «плывёт» в центр. Заголовок раздела 18/700 + пояснение 13 `ink-3`.
- **Группа** (`Group`): тихий заголовок 13/600 над **одной плиткой** `tile` (r16, padding 4);
  строки внутри разделены воздухом, без линий и без «2 px фона» W1. `plain` — для содержимого не
  из строк.
- **Строка** (`Row`): мин. 60 px, padding 12, r12 (концентрично плитке); иконка — колодец 32
  (`track`, r8); подпись 13/600 + пояснение 12 `ink-3` слева, контрол справа; `stack` — контрол
  под текстом (с отступом под колодец). Ошибка — плашка `track` r8 с иконкой (`role="alert"`),
  примечание — `ink-2` с иконкой. Снипет `control` получает `{ labelledby, describedby }` —
  `Toggle`/`SegmentedControl`/`Dropdown` ссылаются на пояснение и ошибку строки
  (`aria-describedby`), строка остаётся ARIA-группой.
- **Контролы:** кнопки, поля (`TextInput`, `SearchField`, имя сниппета), дропдауны, сегменты,
  запись хоткея — капсулы 36; поле с ошибкой — поднятое (`raised` + тень), без цвета. Запись
  хоткея: капсула из kbd 24 (на отступе 6), во время записи — инверсия ink. Тело сниппета —
  сквиркл r12, растёт по тексту (`field-sizing: content`, без уголка ресайза), метки плейсхолдеров
  — смывка без обводки.
- **Расположение шелфа** (`PositionPicker`): пять плиток с мини-экраном 64 × 40 и полкой; выбранная
  — `raised` + тень + полка `ink`, остальные тихие до наведения; радиогруппа со стрелками.
- **Списки в плитке** (папки, приложения, сниппеты): элементы r12 (= 16 − 4) или r8 в плитке
  сниппетов с padding 8; инструменты строки — круги 32, видны при наведении/фокусе.
- **Сниппеты:** две плитки рядом (список 248 px, липкий; редактор), на узком окне — друг под
  другом.
- **Диалоги** (`DialogHost`, `RunningAppsDialog`): `raised`, r28 · padding 12, кнопки 32 в нижних
  углах (концентрично), текст с дополнительным отступом 8; деструктивные — безопасная кнопка в
  фокусе, опасная — `variant="danger"`.
- **Тосты** — общий `Toast` (капсула 40, «Отменить» — ink-капсула).
- Скелетоны той же геометрии (плитка со строками, список, статистика), пустые состояния учат,
  ошибки списков — сообщение + «Повторить», ошибки полей — у поля.
- Деструктивные действия — подтверждение (нативный `<dialog>`: ловушка фокуса, Esc, безопасная
  кнопка в фокусе) и «Отменить», где контракт даёт undo-токен.
- Моушен 150–250 мс, `prefers-reduced-motion` (глобальный гард `app.css`).
- **Онбординг:** шаги слева — капсулы 40, текущий поднят (`raised` + тень), номер — круг 24
  (`ink` у текущего и пройденных, ✓ у пройденных); над шагом — «Шаг N из M» и **капсульный
  счётчик 96 × 6** вместо полосы во всю ширину; иконка шага — ink-колодец 48 r16, заголовок 22/700
  `ink`, пояснение 14 `ink-2`, пункты — колодцы 32 r8. **«Готово» прячет окно**
  (`getCurrentWindow().hide()`, право `core:window:allow-hide`), если `onboardingDone` сохранилось
  — следующий шаг пользователя — сразу `Alt + V`; при следующем открытии — обычные настройки.
  «Пропустить» окно не прячет.

## 8. Отклонения и открытые вопросы

- **`snippet_move`** — в контракте нет команды порядка сниппетов. UI готов (drag, Alt+↑/↓) и зовёт
  `call("snippet_move", { id, beforeId })` из `sections/Snippets.svelte`; пока команды нет, первая
  попытка откатывается и список пишет, что порядок появится позже. Предложено координатору
  (форма как у `folder_move`).
